# TrenchTrack

Free public dashboard of NFL offensive-line stats and letter grades, one page per team, plus a league-wide sortable stats table. Phase 1 (32 team pages, no accounts/payments) is **built and live**, now with multi-season support (2021-2025), Pro Bowl/All-Pro badges, a weekly grade trend chart, a 2026 preview season (blank grades, projected depth chart, free-agency gained/lost), and rule-based Player Archetype labels on player pages. User is a coding beginner — briefly explain non-obvious decisions, don't over-comment code.

## Stack & structure
```
web/        Next.js 16 (App Router, Turbopack), TypeScript, Tailwind v4, deployed on Vercel
pipeline/   Python (nflreadpy) — pulls nflverse data, computes grades, writes to Supabase
supabase/   schema.sql + seed_teams.sql (hand-run in Supabase SQL Editor, no CLI set up)
```

## Commands
- Dev server: `npm run dev --prefix web` (or the `trenchtrack-web` launch.json config)
- Build check: `npm run build --prefix web`
- Pipeline (from `pipeline/`): `venv/bin/python pull_and_compute.py` — pulls fresh data + recomputes all grades for the **current** season (`CURRENT_SEASON`)
- Backfill a past season (from `pipeline/`): `venv/bin/python backfill_season.py 2024 2023 ...` — recomputes `team_ol_stats` + `ol_depth_chart` for any season(s); deliberately does NOT touch `players`/`injuries` (current-snapshot-only tables)
- Pipeline tests: `venv/bin/pytest tests/` (from `pipeline/`)
- Recompute grades only (no data re-pull): `/internal/espn-entry` page button, or `POST /api/recompute-grades`
- Recompute player archetypes (from `pipeline/`): `venv/bin/python compute_player_archetypes.py` — classifies every tracked OL into a Player Archetype + reason bullets, upserts `player_archetypes`. Not part of `pull_and_compute.py`; run manually whenever combine/honors/depth-chart data changes.

## Important gotchas (cost real time to (re)discover — don't re-derive)
- **Next.js 16 renamed `middleware.ts` → `proxy.ts`.** This project already uses `proxy.ts`. This Next version has other real breaking changes vs typical training data — check `web/node_modules/next/dist/docs/` before assuming an API/convention.
- **`pipeline/venv` needs Python 3.10+** (`nflreadpy` requires it); system Python here is 3.9. Built via `uv venv --python 3.12 venv`. `uv`-created venvs have **no `pip`** — use `uv pip install X --python venv/bin/python`, not `pip install`.
- **This shell's Bash tool doesn't reliably pick up `.zshenv`/`.zshrc` PATH changes** between calls. Node/npm, `uv`, and `gh` are symlinked into `~/opt/anaconda3/bin` (already on PATH every call) rather than relying on nvm's own PATH injection. The Bash tool's cwd also doesn't persist reliably across turns — `cd` into `pipeline/` at the start of a turn rather than assuming a prior `cd` stuck.
- **Supabase "Automatically expose new tables" being off** (recommended setting) skips default grants for `service_role`, not just `anon`/`authenticated` — `schema.sql` has explicit `grant ... to service_role` statements because of this.
- **HTTP Basic Auth + client-side `fetch()` don't mix well** (the browser can hang on an invisible re-auth prompt) — `/internal/*` uses a cookie-based login (`proxy.ts` + `app/internal/login/`) instead, not Basic Auth.
- **Native `<datalist>` always shows its full option list on focus/click, no matter how few options exist or what's been typed** — there's no way to suppress that browser behavior from the app side. Both the header's team search (`web/components/TeamSearch.tsx`, 32 options) and the old ESPN player search (~550 options, since removed) hit this for different reasons — one wanted empty-until-typed filtering, one had a real lag problem — and both ended up as a hand-built filtered dropdown instead of `<datalist>`. Default to a custom dropdown over `<datalist>` for any new search/autocomplete here.
- **Grading formula is duplicated in two languages on purpose**: `pipeline/compute_grades.py` (Python, source of truth, run by the full pipeline) and `web/lib/computeGrades.ts` (TS port, used only by the recompute-grades button). Both have "keep in sync" comments pointing at each other — change one, change both, and re-verify they produce bit-for-bit identical output on real data.
- **`nflreadpy.load_depth_charts()` returns two different schemas** depending on whether nflverse has reprocessed that season into its tidy per-week archive yet. A completed prior season gets `week`/`game_type`/`depth_position`/`club_code` columns directly. A season not yet archived (true for the current season, likely true for any season right after it ends) instead returns its raw day-by-day scrape history — `dt`/`team`/`pos_abb`/`pos_rank`, a real snapshot for literally every calendar day, just not bucketed into weeks. `pipeline/steps/pull_ol_depth_chart.py` detects which schema it got and, for the unarchived case, buckets days into real NFL weeks itself using `nflreadpy.load_schedules()` — don't assume the tidy schema unconditionally when touching this data.
- **No reliable player-ID crosswalk exists between PFR (snap counts) and ESPN (depth-chart side-of-ball) for offensive linemen specifically** — nflverse's own crosswalk (`load_rosters()`'s `pfr_id` column) has ~0% coverage for OL (it's populated for skill positions, not linemen). `pull_ol_depth_chart.py` joins the two sources by normalized player name instead (~97%+ match rate league-wide; the unmatched remainder is deep bench players who never rank in a team's top spots anyway).
- **PFR's snap-count position tag added a new generic `"OL"` catch-all starting in the 2025 season** (previously always a specific `T`/`G`/`C`) — `pull_ol_depth_chart.py`'s position filter already accounts for this; watch for the same kind of source-schema drift in future seasons.
- **PFR's advanced-stats/snap-count sources still tag the Raiders `"OAK"` for 2018-2019** (pre-Vegas-move) while other nflverse sources already normalize to `"LV"` — `pull_team_ol_stats.py` remaps this before joining. If seasons before 2018 are ever added, expect the same issue for the Chargers (`SD`) and Rams (`STL`).
- **Manually-researched external data** (ESPN win rates, Pro Bowl/AP All-Pro honors) is entered via one-off scripts using `write_to_supabase.get_client()` directly, run from the scratchpad — **not** part of the tracked `pipeline/` codebase, since it's hand-compiled data `nflreadpy` doesn't provide rather than a recurring automated pull. Follow this same pattern for any future manually-sourced data.
- **No charting library is installed.** The Team Stats "Chart It" bar chart (`web/components/TeamStatsBarChart.tsx`) is hand-built HTML/CSS/SVG — single-hue bars (not per-team categorical colors), per the dataviz skill's guidance that a magnitude comparison across many categories (32 teams) is a sequential/one-hue job, not an identity/categorical one. `TeamGradeTrendChart.tsx` (the per-team weekly trend line) is the identity case instead — 3 fixed categorical colors (`--series-overall/pass/run` in `globals.css`, validated with the dataviz skill's `validate_palette.js`), one metric shown at a time via small tabs. Follow the dataviz skill for any new chart rather than reaching for a library or defaulting to per-item colors.
- **For a season with no games played yet** (e.g. previewing next year before it starts), `nflreadpy.load_depth_charts()` still returns something useful: ESPN's live, continuously-updated current depth chart (the same unarchived day-by-day schema described above, just for a season with a single "today" snapshot instead of a real week to bucket into). `pull_projected_depth_chart.py` takes that latest snapshot's `pos_rank` directly as `depth_rank`, skipping the snap-count join entirely (there are no snaps yet). Hand-cross-checked against Ourlads.com (free, no login, abbreviations mostly match nflverse except `ARZ`/`LAR` for Cardinals/Rams) for the 2026 rollout — starters matched exactly on 30/32 teams; the 2 real disagreements (not just interchangeable-backup noise) were resolved against team beat-writer sources before writing. `ol_depth_chart.snaps` is nullable specifically for these rows — the page shows "Projected" instead of a snap count when it's null.
- **Free-agency gained/lost (`ol_free_agency_moves`) needed zero manual research**, unlike the ESPN-win-rate/Pro-Bowl pattern below — it's a pure join between data already in this DB (`ol_depth_chart`'s real snap totals for the past 2 seasons) and `nflreadpy.load_rosters()` for the season being previewed, matched by `gsis_id` (which `ol_depth_chart.player_id` already reliably is — checked 0% null coverage). See `pull_free_agency_moves.py`.

## Design system ("Turf")
CSS custom properties in `web/app/globals.css`, registered as Tailwind v4 theme tokens (no `tailwind.config.js`): stone/chalk background, deep turf-green accent (`--accent`), a 5-step "turf to rust" grade-letter color ramp (`--grade-a`...`--grade-f`), plus one-off NFC blue / AFC red tokens (`--nfc-accent`/`--afc-accent`) used only on the homepage's conference split. Single fixed light theme — dark mode deliberately dropped for now. `GradeBadge` (`web/components/GradeBadge.tsx`) exports `GRADE_COLOR_VARS` (grade letter → CSS var name) for reuse anywhere else that needs grade-consistent coloring outside the badge itself (e.g. the homepage's compact team cards, `HonorBadge`'s All-Pro gold, `SeasonTabs`' optional grade-in-tab mode); it also takes an optional `className` for embedding in tighter layouts. Its numeric score is intentionally hidden by default (`opacity-0`, absolutely positioned so it doesn't affect the badge's height) and only fades in as a small tooltip on hover — the letter grade + league rank are the always-visible summary, the exact score is a deliberate secondary reveal, not a missing feature.

## Grading (`pipeline/compute_grades.py` — read its docstring for the full writeup)
Three grades per team per week: Pass Block, Run Block, Overall. Every raw stat is min-max normalized against that week's 32 teams (curved/relative, not absolute), then blended:
- **Pass Block**: sack rate 20% / pressure rate allowed 40% / ESPN Pass Block Win Rate 40% (weighted on purpose — pressure rate is a more stable O-line signal than raw sacks, which are partly a QB/scheme stat)
- **Run Block**: stuff rate / yards before contact per att / ESPN Run Block Win Rate — equal thirds (unweighted so far)
- Missing ESPN data doesn't break the score — its weight drops out and the rest renormalize.
- Each of the three blended scores then gets a **second min-max stretch** across that week's 32 teams before mapping to a letter — without this, averaging several already-normalized components compresses everyone toward the middle and nobody ever hits a true 0 or 100 (A+/F sit empty). The stretch guarantees the week's actual best team hits exactly 100 and the actual worst hits exactly 0.
- Scores map to letters on **equal-width** 13-band scale (not the traditional 60%-is-passing school scale — that would wrongly dump most teams into "F" for a curved score; see docstring).
- `grade_formula_version` column tracks formula changes (currently `"v3"`).

## Data model notes
- `team_ol_stats` stores **weekly history** (one row per team/week, never overwritten) — enables a future "grade over the season" chart.
- `ol_depth_chart` stores real **season history** (not a current-only snapshot): every player who logged offense snaps at each O-line position that season, ranked by total snaps (`depth_rank` 1 = most). This replaced the old `ol_starters` table (removed — its pipeline step broke when nflreadpy changed its depth-chart schema, and the replacement is strictly richer: shows real backups too, and works for every past season, not just "today"). `snaps` is nullable — null means a **projected** row (see the gotcha above), not a real season.
- `ol_free_agency_moves` — for a season being previewed before it starts, the 300+-snap O-line players each team gained/lost that offseason. Stored from both sides (`direction` = `gained`/`lost`) so either team's page queries by its own `team_abbr` alone. Fully derived, not hand-entered — see the free-agency gotcha above.
- `player_honors` stores hand-entered Pro Bowl / AP All-Pro (1st/2nd team) selections per season, joined to `ol_depth_chart` rows by `player_name` in `web/lib/getTeamPageData.ts`. AP All-Pro only (not PFF, Sporting News, etc).
- `injuries` stores only the **current** snapshot (not history) — this is why past-season team pages hide that section entirely (`isCurrentSeason` gate) rather than mislabeling today's roster as historical.
- `teams` (32 rows) is seeded once by hand (`seed_teams.sql`), not auto-synced by the pipeline.
- `SUPPORTED_SEASONS` is currently `[2021, 2022, 2023, 2024, 2025, 2026]`; `CURRENT_SEASON = 2025` — both hardcoded in `web/lib/teamsStatic.ts`. A season past `CURRENT_SEASON` with no real `team_ol_stats` rows yet (2026 today) is a **preview season**: grade badges/metrics/trend-chart sections all already no-op on `stats === null`/empty arrays, so adding one is just appending to `SUPPORTED_SEASONS` — don't bump `CURRENT_SEASON` until the season actually starts (that also correctly keeps the injury-report section off). Bump `CURRENT_SEASON` + redeploy once real games start, then run `backfill_season.py` for it.
- Season is in the URL for both team pages (`/team/[slug]/[season]`) and the league-wide stats table (`/stats/[season]`) — `SeasonTabs` (`web/components/SeasonTabs.tsx`) takes a `basePath` prop so the identical component drives the season switcher on both, plus optional `grades`/`gradeLayout` props to show each season's Overall grade in the tab itself (used on team pages, not `/stats`).
- `player_archetypes` stores one row per `player_id` (not per-season — a "current best classification" from career draft/combine/snap-history data, same model the script uses), rule-derived by `pipeline/compute_player_archetypes.py` from data already in this DB. `reasons` is a short text array of ready-to-render bullets (e.g. `"90th %ile weight"`), not meant to be parsed apart. Unlike `player_honors`, this isn't hand-entered, but it's also not wired into the automatic pipeline (see the Commands entry above) since the rules are hand-tuned enough to warrant running it deliberately. Player pages are statically generated with a 24h ISR revalidate and nothing calls `revalidatePath` after this script runs (unlike `/api/espn-entry`/`/api/recompute-grades`), so a fresh archetype run won't show up live until the next daily regeneration.

## Known MVP shortcuts (intentional, revisit later)
No auth beyond one shared password on `/internal/*` · pipeline runs manually, no cron yet · no CI on the Python side · donation link removed for now, pending a real Ko-fi/BMC URL.

Note: `/api/espn-entry` and `/api/recompute-grades` both call `revalidatePath("/", "layout")` on success, so ESPN entries and grade recomputes show up on next page visit rather than waiting for the daily ISR window. The Python pipeline itself does **not** call this (it has no way to reach a Next.js route) — after a full `pull_and_compute.py` run, either wait for the daily revalidation or hit `/api/recompute-grades` once to force an immediate refresh.
